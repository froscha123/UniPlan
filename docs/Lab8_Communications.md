# ЛР №8 — Управление коммуникациями в проекте UniPlan

## Ключевые стейкхолдеры
1. Заказчик / куратор проекта
2. Проектный менеджер
3. Бизнес-аналитик
4. Backend-разработчик
5. Frontend/UX-разработчик
6. Тестировщик
7. IoT-специалист
8. Представитель пользователей

## План коммуникаций
| Вид информации | Кому | Канал | Периодичность | Ответственный | Цель |
|---|---|---|---|---|---|
| Еженедельный статус проекта | Заказчик, команда | Email + GitHub Projects | Еженедельно | ПМ | Прогресс, сроки, риски |
| Оперативная синхронизация | Команда | GitHub Projects + мессенджер | Ежедневно | ПМ | Уточнение текущих задач |
| Изменение требований | Заказчик, ПМ, аналитик | Онлайн-встреча + GitHub Issue | По необходимости | Бизнес-аналитик | Зафиксировать и согласовать изменение |
| Ревью интерфейса | ПМ, Frontend/UX, пользователи | Figma / видеовстреча | Раз в 2 недели | Frontend/UX | Согласовать UX и прототипы |
| Баг-репорты | Тестировщик, разработчики | GitHub Issues | По факту / ежедневно | Тестировщик | Быстро устранить дефекты |
| IoT-интеграция | Backend, IoT, ПМ | GitHub + видеовстреча | Еженедельно на этапе IoT | IoT-специалист | Согласовать API, данные и безопасность |
| Результаты этапа / релиз | Все ключевые стейкхолдеры | Презентация + отчёт | По завершении этапа | ПМ | Подтвердить результат и следующие шаги |

## RACI
Обозначения: **R** — выполняет работу, **A** — отвечает за итоговый результат, **C** — консультирует, **I** — информируется.

| Задача | ЗК | ПМ | БА | BE | FE/UX | QA | IoT | ПП |
|---|---|---|---|---|---|---|---|---|
| Сбор и уточнение требований | C | A | R | I | I | C | I | C |
| Согласование состава MVP | A | R | C | I | I | C | I | C |
| Проектирование структуры данных | I | A | C | R | I | C | C | I |
| Проектирование UX-прототипа | C | A | C | I | R | C | I | C |
| Описание API и уведомлений | I | A | C | R | C | C | C | I |
| Мультиязычный интерфейс | I | A | C | I | R | C | I | C |
| Реализация задач и дедлайнов | I | A | C | R | R | C | I | I |
| Индикатор учебной нагрузки | I | A | C | R | R | C | I | C |
| IoT-прототип и обмен данными | I | A | C | R | I | C | R | I |
| Пользовательское тестирование | I | A | C | I | C | R | I | R |
| Пилотный запуск | A | R | C | I | I | C | I | C |

## Пример отчёта по коммуникациям
- **Дата:** 30.11.2026
- **Участники:** ПМ, бизнес-аналитик, Backend, Frontend/UX, тестировщик, представитель пользователей.
- **Решения:** единый формат баг-репортов; индикатор нагрузки остаётся в MVP; IoT проверяется отдельным прототипом; решения встречи фиксируются в GitHub.
- **Открытые вопросы:** формат уведомлений, список поддерживаемых IoT-устройств, сроки расширения мультиязычности.
- **Следующие шаги:** QA готовит тест-кейсы, Backend уточняет API, Frontend/UX корректирует прототип, ПМ обновляет план и назначает ревью.

## Вывод
План коммуникаций снижает риск потери требований и недопонимания благодаря единой фиксации задач и решений в GitHub, регулярным статусам и ревью, а также правилу одного Accountable на каждую задачу.
